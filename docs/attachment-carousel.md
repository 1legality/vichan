# Attachment carousel

`js/attachment-carousel.js` and `js/media-viewer.js` are independently registered through `additional_javascript`. `templates/header.html` loads each script's corresponding scoped stylesheet, including when scripts are compiled into `main.js`. Removing either script disables that feature without disabling the other or seasonal decorations.

All non-empty `.files` groups receive a compact filename caption. Groups with two or more direct `.file` children also show an attachment count, the active media, and Previous/Next buttons around directly selectable thumbnails. The position counter is available to screen readers without taking visual space. A quieter Show all / Show one button switches between the gallery and the full set. Navigation wraps and never rotates automatically. All files remain accessible when JavaScript is disabled. Single-file posts keep their thumbnail dimensions inside the shared media frame and have no carousel controls. Their original metadata stays in the DOM for other scripts, while optional moderation, image lookup, video loop and hide/show controls remain available.

The carousel uses up to 360px including its 8px padding and 1px border, capped to the available width so the frame stays close to its media. Single and multiple attachments use the same thin theme border, 4px corners and transparent background. The frame retains the surrounding post color instead of adding a separate filled panel. Only multiple attachments add a compact header and navigation. OP and reply captions share an explicit 6px gap, and both text columns use the same 20px separation from the media frame. On desktop, the reply header aligns with the top of the media frame and its text follows below. Single-file frame width includes its inset so the media itself is not reduced. A 255px thumbnail stage keeps navigation in place across image proportions without enlarging the generated thumbnail file. On desktop, the OP and replies place their header and text beside the media; replies begin below the OP media. Below 768px, the text stacks underneath. Show all and inline expansion can use the full width. Square thumbnails sit between the two arrows below the filename. Three 64px thumbnails fit on each row at full width; incomplete rows are centered. Five attachments use two rows and ten use four. Thumbnail targets stay at least 44px on narrow screens. Selecting an attachment does not scroll the page. Previews use `object-fit: contain` to preserve the entire image, including spoiler and document placeholders. Only the selected attachment's original filename appears directly beneath the main image, before the navigation bar, as a download link when available. Long filenames wrap within the gallery. Show all restores the complete file information for each attachment. Cyberpunk uses dark purple controls, lavender borders, and an emphasized outline on the selected thumbnail. Dark uses dark controls with a green focus indicator, Yotsuba B uses pale blue controls with navy accents, Yotsuba/Futaba use cream controls with maroon accents, and Photon uses gray controls with blue accents. Thumbnail backgrounds use the same palette as the controls. Cyberpunk and Dark retain gray backing behind images and previews for transparent artwork and placeholders, while the media viewer uses gray image backing in every theme so transparent artwork stays legible. CSS chevrons keep both navigation arrows visible without an icon font; each button has an accessible Previous/Next label.

Clicking an image or video opens the media viewer at that attachment without expanding the post. Its Previous/Next controls navigate the current post's supported media and synchronize the inline carousel selection. Documents and deleted files are skipped; playable videos remain available when thumbnail generation falls back to a file icon. When the optional legacy Expand all control is present, it becomes View all media and opens the supported media from visible posts in one viewer. Show all remains an inline layout toggle and does not open or preload every attachment.

The dialog header and thumbnail toolbar follow the selected board theme: blue-gray for Yotsuba B, beige and maroon for Yotsuba/Futaba, gray and blue for Photon, dark gray and green for Dark, and purple for Cyberpunk. The media stage stays dark in every theme, with separate light colors for loading/error text, focus rings and scrollbars. The dialog header places a small filename link at the top left in place of the generic title, truncating long names as needed while keeping Close at the right. The footer contains a single horizontal thumbnail row, with Previous and Next on either side. Square thumbnails are 64px on desktop and 44px on mobile or in viewports no taller than 500px. Longer collections scroll horizontally within the rail; they do not wrap. A single item hides the entire navigation row while keeping the filename available. Selection uses an outline only and updates the media, filename link, navigation, and inline carousel together. Clicking the current thumbnail preserves playback and zoom. The rail has one tab stop; Left/Right and Home/End select in file order, move focus, and reveal the selection by scrolling only the rail. Previews reuse existing thumbnails or video posters, preserve spoilers, freeze GIF frames, and fall back to attachment numbers when unavailable. They never preload originals. Hidden images use the numbered fallback in both rails; Show restores their thumbnail previews, and delayed GIF loads cannot reveal them while hidden.

The viewer provides a fitted image or native video controls, the filename link, thumbnail navigation, and Close. There is no visible attachment counter or separate Open original button. Clicking the filename downloads same-origin media with its original filename. For cross-origin media, the link opens the original in a new tab because the browser cannot guarantee a download without an attachment response header. Escape, Close, a click outside the panel, or the browser Back action dismisses it without leaving the page. Opening adds one same-URL history entry; changing attachments updates that entry instead of adding more. Close, Escape, and backdrop clicks return to the page entry, while Forward can reopen the selected attachment. Left/Right and Home/End navigate; native video keyboard controls keep their keys. When navigation replaces the focused image, focus moves to the selected thumbnail so further keys keep working during loading or after a load failure. Tab stays within the modal. There is no separate zoom button: a single mouse click on the image toggles fitted and original size only when its original dimensions exceed the available frame. Images that already fit stay centered, with no zoom cursor or keyboard zoom control. Zoom availability updates when the frame is resized. Zoomable images are keyboard-focusable, with Enter/Space performing the same action. At original size, scroll or use the focused image viewport's arrow keys to pan; Enter/Space returns to fit. Mobile keeps the browser's native pinch zoom and panning. A horizontal touch swipe navigates fitted images while the browser viewport is not zoomed. Page scrolling is locked while open; closing restores the page's scroll position and focus to the selected thumbnail when available.

Only the selected original is requested, including a spoiler explicitly selected in the viewer. Other originals are not prefetched. Videos start playing when opened or selected through viewer navigation, using the configured volume/mute preference and the attachment's play-once/loop choice. If the browser denies autoplay, the viewer retries once muted; native controls remain available if playback is still blocked. The previous video stops when navigating or closing. This autoplay behavior applies only to the viewer; inline thumbnail and hover playback settings remain unchanged. Loading failures keep the filename link available and direct the user to the appropriate action. Modified clicks keep native link behavior. Explicitly enabled gallery mode keeps ownership of its links. Without the viewer script or the native dialog API, existing links and legacy expansion handlers remain available; only that fallback retains the carousel's inline expansion-state handling.

Buttons support keyboard Tab, Enter, and Space, with a minimum 44px target. With focus in the carousel controls or thumbnail rows, Left/Right and Home/End select attachments in file order. The thumbnails use one tab stop and move focus with the selected thumbnail. Selection has an emphasized border and `aria-current`; the visually hidden counter is a polite live region. These keys are not captured in media controls, comment fields, or elsewhere on the page. Show one restores the selected attachment after Show all.

Files remain direct children of their original group in their original order, including opening-post attachments outside `.post.op`. Inside each file, original metadata remains before the media link for compatibility with image-hiding scripts. The compact filename, shared navigation and thumbnail rows follow the active media. Keyboard focus is preserved across this move. `data-file-index` records Twig's original `loop.index0`; moderation URLs still use that same original index. Media anchors, filenames, dimensions, download links, spoilers, file icons, and deleted placeholders remain intact. Uploads and storage are unchanged.

Initialization is idempotent and uses `new_post`. A small mutation observer also handles hover previews cloned without that hook. Clones rebuild their own controls and discard inherited expansion artifacts; frozen GIF canvases are redrawn without exposing their hidden animated source. Inactive videos/audio are paused, including delayed playback events, and are never automatically resumed by navigation. Thumbnail previews reuse only existing thumbnail URLs or video posters, retaining spoiler and deleted-file placeholders. GIF previews are captured as static frames; failed or unavailable previews fall back to attachment numbers. The carousel does not preload full-size attachments. Gallery navigation selects the corresponding attachment, skips document/deleted icons, and pauses old video playback; switching gallery mode off restores the normal link handlers.

For installation, rebuild and cache steps, see [Seasonal decorations](seasonal-events.md#configuration-and-rebuilding). These features can be tested on a temporary local page without publishing or activating the application.

The gallery boundary follows the [common-region grouping principle](https://www.nngroup.com/articles/common-region/): use one restrained container to make related controls and content recognizable. Navigation retains visible buttons, keyboard focus and at least 44px targets, following the [W3C carousel styling guidance](https://www.w3.org/WAI/tutorials/carousels/styling/).
