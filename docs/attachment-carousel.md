# Attachment carousel

`js/attachment-carousel.js` and `js/media-viewer.js` are independently registered through `additional_javascript`. `templates/header.html` loads each script's corresponding scoped stylesheet, including when scripts are compiled into `main.js`. Removing either script disables that feature without disabling the other or seasonal decorations.

Only `.files` groups with two or more direct `.file` children are enhanced. Each group shows an attachment count, the active media, Previous/Next buttons, an `N of M` counter, and directly selectable thumbnails. A quieter Show all / Show one button switches between the gallery and the full set. Navigation wraps and never rotates automatically. All files remain accessible when JavaScript is disabled. Single-file posts retain their original presentation without carousel controls.

The carousel stays compact at 360px, capped to the available width. A 255px thumbnail stage keeps navigation in place across image proportions. Square thumbnails form centered rows beneath the photo, with at most five per row: ten attachments produce two rows of five, and incomplete rows remain centered. Thumbnail targets shrink to 44px at a 320px viewport and are capped at 64px on desktop. All rows stay visible without horizontal scrolling. Previews use `object-fit: contain` to preserve the entire image, including spoiler and document placeholders. Only the selected attachment's original filename appears beneath the thumbnail rows, as a download link when available. Long filenames wrap within the gallery. Show all restores the complete file information for each attachment. Cyberpunk uses dark purple controls, lavender borders, and an emphasized outline on the selected thumbnail. Dark uses dark controls with a green focus indicator, Yotsuba B uses pale blue controls with navy accents, Yotsuba/Futaba use cream controls with maroon accents, and Photon uses gray controls with blue accents. Thumbnail backgrounds use the same palette as the controls. Cyberpunk and Dark retain gray backing behind images and previews for transparent artwork and placeholders, while the media viewer uses gray image backing in every theme so transparent artwork stays legible. Existing Font Awesome icons are used when available, with visible text labels as the fallback.

Clicking an image or video opens the media viewer at that attachment without expanding the post. Its Previous/Next controls navigate the current post's supported media and synchronize the inline carousel selection. Documents and deleted files are skipped. When the optional legacy Expand all control is present, it becomes View all media and opens the supported media from visible posts in one viewer. Show all remains an inline layout toggle and does not open or preload every attachment.

The dialog header and thumbnail toolbar follow the selected board theme: blue-gray for Yotsuba B, beige and maroon for Yotsuba/Futaba, gray and blue for Photon, dark gray and green for Dark, and purple for Cyberpunk. The media stage stays dark in every theme, with separate light colors for loading/error text, focus rings and scrollbars. The dialog header places a small filename download at the top left in place of the generic title, truncating long names as needed while keeping Close at the right. The footer contains a single horizontal thumbnail row, with Previous and Next on either side. Square thumbnails are 64px on desktop and 44px on mobile or in viewports no taller than 500px. Longer collections scroll horizontally within the rail; they do not wrap. A single item hides the entire navigation row while keeping the filename available. Selection uses an outline only and updates the media, filename download, navigation, and inline carousel together. Clicking the current thumbnail preserves playback and zoom. The rail has one tab stop; Left/Right and Home/End select in file order, move focus, and reveal the selection by scrolling only the rail. Previews reuse existing thumbnails or video posters, preserve spoilers, freeze GIF frames, and fall back to attachment numbers when unavailable. They never preload originals. Hidden images use the numbered fallback in both rails; Show restores their thumbnail previews, and delayed GIF loads cannot reveal them while hidden.

The viewer provides a fitted image or native video controls, the filename download, thumbnail navigation, and Close. There is no visible attachment counter or separate Open original button. Clicking the filename downloads the currently selected original media with its original filename. Escape, Close, or a click outside the panel dismisses it. Left/Right and Home/End navigate; native video keyboard controls keep their keys. When navigation replaces the focused image, focus moves to the selected thumbnail so further keys keep working during loading or after a load failure. Tab stays within the modal. There is no separate zoom button: a single mouse click on the image toggles fitted and original size only when its original dimensions exceed the available frame. Images that already fit stay centered, with no zoom cursor or keyboard zoom control. Zoom availability updates when the frame is resized. Zoomable images are keyboard-focusable, with Enter/Space performing the same action. At original size, scroll or use the focused image viewport's arrow keys to pan; Enter/Space returns to fit. Mobile keeps the browser's native pinch zoom and panning. A horizontal touch swipe navigates fitted images while the browser viewport is not zoomed. Page scrolling is locked while open; closing restores the page's scroll position and focus to the selected thumbnail when available.

Only the selected original is requested, including a spoiler explicitly selected in the viewer. Other originals are not prefetched. Videos start playing when opened or selected through viewer navigation, using the configured volume/mute preference and the attachment's play-once/loop choice. If the browser denies autoplay, the viewer retries once muted; native controls remain available if playback is still blocked. The previous video stops when navigating or closing. This autoplay behavior applies only to the viewer; inline thumbnail and hover playback settings remain unchanged. Loading failures keep the filename download available and direct the user to it. Modified clicks keep native link behavior. Explicitly enabled gallery mode keeps ownership of its links. Without the viewer script or the native dialog API, existing links and legacy expansion handlers remain available; only that fallback retains the carousel's inline expansion-state handling.

Buttons support keyboard Tab, Enter, and Space, with a minimum 44px target. With focus in the carousel controls or thumbnail rows, Left/Right and Home/End select attachments in file order. The thumbnails use one tab stop and move focus with the selected thumbnail. Selection has an emphasized border and `aria-current`; the counter is a polite live region. These keys are not captured in media controls, comment fields, or elsewhere on the page. Show one restores the selected attachment after Show all.

Files remain direct children of their original group in their original order, including opening-post attachments outside `.post.op`. Inside each file, metadata moves after the media; shared navigation and the thumbnail rows move into the active file before that metadata. Keyboard focus is preserved across this move. `data-file-index` records Twig's original `loop.index0`; moderation URLs still use that same original index. Media anchors, filenames, dimensions, download links, spoilers, file icons, and deleted placeholders remain intact. Uploads and storage are unchanged.

Initialization is idempotent and uses `new_post`. A small mutation observer also handles hover previews cloned without that hook. Clones rebuild their own controls and discard inherited expansion artifacts; frozen GIF canvases are redrawn without exposing their hidden animated source. Inactive videos/audio are paused, including delayed playback events, and are never automatically resumed by navigation. Thumbnail previews reuse only existing thumbnail URLs or video posters, retaining spoiler and deleted-file placeholders. GIF previews are captured as static frames; failed or unavailable previews fall back to attachment numbers. The carousel does not preload full-size attachments. Gallery navigation selects the corresponding attachment, skips document/deleted icons, and pauses old video playback; switching gallery mode off restores the normal link handlers.

For installation, rebuild and cache steps, see [Seasonal decorations](seasonal-events.md#configuration-and-rebuilding). These features can be tested on a temporary local page without publishing or activating the application.
